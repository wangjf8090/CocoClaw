## v3.6.1 增量变更（2026-06-15）

> **背景**：参考 2026-06-15 Agent World 调研日报的 4 个爆款 Skill：
> - addyosmani/agent-skills — 24 个 TDD 技能 + 「反合理化表」机制
> - Leonxlnx/taste-skill — 「强制完整输出」技能
>
> 主人 6/15 拍板把这两个机制补到 Skill Cleaner 三件套（audit/optimize/lifecycle）。

### 1. 反合理化表（Anti-Rationalization Table）

**解决问题**：Agent 用"改动小""临时方案"等借口跳过测试/省略步骤。

**核心思路**：检测到跳步行为时，强制要求 Agent 引用反合理化表中的反证话术 + 审计日志记录。

**反合理化表（10 条）**：

| 类型 | 借口描述 | 反证话术要点 |
|------|---------|------------|
| skip_test | 改动很小，不需要测试 | 任何改动都可能引入 bug |
| skip_test | 暂时跳过测试，后续再加 | 没有测试的代码不可维护 |
| skip_test | 显而易见，不需要测试 | 自动化测试防止意外退化 |
| omit_step | 省略某些步骤，简化流程 | 省略步骤隐藏重要逻辑 |
| ignore_lint | 忽略 lint 警告，以后再修 | lint 是代码质量信号灯 |
| assume_safe | 应该没问题，不用验证 | 程序需要确定性验证 |
| copy_paste | 直接复制粘贴就行 | 复制粘贴是技术债源头 |
| lazy | 懒得写测试了 | 懒惰以加倍成本偿还 |
| lazy | 临时方案，很快会改 | 临时方案常变永久 |
| skip_test | 不影响核心功能，不用测 | 边缘场景也可能出问题 |

**集成点**：`skill-audit.ts` 在跳步检测处调用反合理化表。

### 2. 强制完整输出（Forced Complete Output）

**解决问题**：LLM 长输出中途截断（句末标点缺失、代码块未闭合、JSON 大括号不平衡）。

**核心思路**：4 种完整性启发式检查 + Continue 续写机制。

**4 种启发式**：

| # | 启发式 | 检查内容 | 严重程度 | 扣分 |
|---|--------|---------|---------|------|
| 1 | `sentence_ending` | 句末标点检查 | critical | -30 |
| 2 | `code_block_closure` | 代码块闭合检查 | critical | -30 |
| 3 | `markdown_balance` | Markdown 平衡检查 | warning | -10 |
| 4 | `json_brace_balance` | JSON 大括号平衡 | critical | -30 |

**续写机制**：完整性分数 < 阈值时，自动触发 Continue 续写直到完整或达到最大重试次数。

**集成点**：`skill-optimize.ts` 在文档生成末尾调用完整性校验。
